# 完整性：验收项与证据

> 课程图 32/33：验收清单**从前面的需求长出来**，且必须可判定、有证据。
> 只写"已测"不算完成；产物写了而证据没齐，交付仍缺最后一环。

## 验收项

- 每条验收项写成"具体操作 + 预期结果"，可判定（通过/不通过没有争议）；
- 验收项必须能回到 PRD 的对应条目与需求出处；
- 开发过程中发现的新要求（如"是否留导出记录"）**不能悄悄补成既定要求**，
  要回到需求方确认并补进来源链。

## 证据类型

| 类型 | 适用 | 示例 |
|---|---|---|
| 导出文件 | 导出/报表类 | `export-sample.csv`（含列与行数） |
| 日志 | 权限、异常、后台任务 | `log-permission-denied.txt` |
| 截图 | 交互状态 | 空态/报错态/加载态截图 |
| 测试报告 | 逻辑正确性 | pytest 输出（含用例名） |

## 复验方式

- 证据必须能**脱离作者**被复验：写明如何重放（命令、输入、预期）；
- 证据与结论分开存放：结论是"通过"，证据是文件（可 hash 校验）；
- 半年后接手的人只看材料也应能复验——否则视为证据不足。
