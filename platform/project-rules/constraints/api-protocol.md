# 约束：统一接口协议

> 对应课程图 26：同一系统如果有的接口返回 `success/error`、有的返回 `code/msg`，
> 前端就要写多套处理。**固定的是所有模块共享的协议**，让 AI 不能每次重新选择。

## 返回结构

所有 HTTP 接口统一返回：

```json
{"code": 0, "msg": "ok", "data": {}}
```

- `code`：0 表示成功；非 0 为业务错误码（见下）；
- `msg`：人类可读信息（**不得**用于程序判断）；
- `data`：业务数据；无数据时为 `null`，不得省略该字段。

## 错误码

| 区间 | 含义 | 示例 |
|---|---|---|
| 0 | 成功 | — |
| 1xxx | 参数/校验错误 | 1001 缺少必填参数 |
| 2xxx | 权限错误 | 2001 无 export:user 权限 |
| 3xxx | 业务规则冲突 | 3001 超出单次导出行数上限 |
| 5xxx | 服务端错误 | 5001 依赖服务不可用 |

## 分页

- 请求：`page`（从 1 开始）、`size`（默认 20，上限 200）；
- 响应：`data: {items: [], total: 0, page: 1, size: 20}`；
- 超限的 `size` 必须被服务端收敛到上限，并在 `msg` 中说明（不得静默截断）。

## 禁止事项

- 禁止新增自定义顶层字段（如 `result`、`payload`、`success`）；
- 禁止用 HTTP 200 + `msg="失败"` 表达业务失败（必须给非 0 `code`）。
