# 设计：数据字典

> 课程图 34：字段、索引和约束要有业务依据——成本金额为何存在、哪些角色可见、创建时间为何这样处理，
> 都应能回到需求原话及确认。**字段齐全不代表统计正确**；口径错了，页面和导出即使运行正常也不能用于业务判断。

## 字段来源

每个新增字段必须登记：

| 字段 | 类型 | 业务含义 | 来源（需求出处） | 敏感级别 |
|---|---|---|---|---|
| cost_amount | decimal(18,2) | 成本金额 | voice `feishu://.../om_voice_214` @41200ms「成本列运营不能看」 | 财务敏感 |
| warehouse_id | bigint | 仓库维度 | 同上「按月分仓」 | 内部 |
| created_at | timestamptz | 创建时间（UTC 存储） | 平台既有约定 | 内部 |

- **来源列必须是可回查的出处**（消息 ID / 录音时间戳 / 单元格），不能写"业务方说的"；
- 未确认来源的字段标注 `待确认`，并在 PRD/设计里保持可见，不得当作已批准。

## 敏感字段

- 敏感字段必须同时登记"谁能看"：`可见角色: [finance]`；
- 导出/接口默认**不输出**敏感字段，需显式授权（课程图 18 的权限行）。

## 命名约定

- 时间字段统一 `*_at`（`timestamptz`，UTC 存储，展示按 UTC+8）；
- 金额字段统一 `*_amount`（`decimal(18,2)`），禁止用 float；
- 统计口径字段（如聚合维度）写在业务设计里，不靠字段名暗示。
