## 2. 机制验证结论（本批次的真正价值）

| 机制 | 验证结果 |
|---|---|
| 独立用例生成（与研发自测无关） | ✅ 10/10 功能均生成（9 个通过隔离自检） |
| 隔离自检 + 重生成 | ✅ 生成用例不污染既有测试（no-overwrite 生效，全仓 115+ 用例稳定） |
| 全仓回归 | ✅ 生成用例与既有实现差异如实呈现（13~18 个断言偏差/功能） |
| 缺陷闭环（建单→修复尝试→留痕） | ✅ 9 个真实缺陷单创建并关联失败输出；修复尝试后如实保留 |
| **不误合入** | ✅ 任何失败均未合入 main（main 保持 115 全绿） |
| G4 放行决策 | ✅ 9/9 到达 G4，审批三要素含测试结果与缺陷清单，决策耗时 0.7s |
| 报告与审计 | ✅ 测试报告随审批上下文；决策留痕 |

## 3. 已知限制（诚实结论）

- **DeepSeek 生成独立用例质量不稳**：幻觉 API 签名（如 3 参数调用）与预期格式，导致"用例-实现"偏差大；AI 自动修复无法对齐（0/9 闭环率）；
- 影响：独立用例需人工审核后方可作为放行依据；缺陷闭环的"AI 修复"环节当前不可全自动信任；
- 应对（平台侧已就位）：缺陷单留痕、G4 如实上报、不误合入、人工接管；
- 提升方向（后续）：接入更强模型（Claude/旗舰模型）做用例生成与修复；或将独立用例生成改为"测试专家 prompt + 有限工具"模式；单元测试已覆盖"修复成功→回归→关单"完整路径（test_defect_loop_fix_and_close）。
