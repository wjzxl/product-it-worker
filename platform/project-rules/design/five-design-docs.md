# 设计：五份配套设计

> 课程图 29：同一个模块分别出现在数据、业务规则、接口、前端和测试目录里。
> **五份文件不是五次重复，而是五个互相校验的视角**（存什么、怎么算、怎么调用、用户怎么操作、如何证明正确）。

## 五份配套设计

| 视角 | 回答的问题 | 模板 |
|---|---|---|
| 数据 data | 存什么：表、字段、类型、索引、约束 | `templates/data.md` |
| 业务 business | 怎么算：状态流转、校验规则、权限 | `templates/business.md` |
| 接口 api | 怎么调用：路径、入参、出参、错误码 | `templates/api.md` |
| 前端 frontend | 用户怎么操作：布局、组件、交互、各状态 | `templates/frontend.md` |
| 测试 test | 如何证明正确：用例与证据 | `templates/test.md` |

## 不适用声明

没有该视角的模块**必须显式声明**，而不是悄悄删掉：

```yaml
frontend:
  not_applicable: true
  reason: "后台定时任务，无页面"
```

工程闸门 E2 会拒绝"缺失且未声明"的模块——**区分「经过确认的空」与「漏掉的空」**（课程图 30）。

## 互相校验

五份设计之间有交叉约束，至少检查：

- 接口出参字段 ∈ 数据设计字段（不得返回未定义的字段）；
- 业务规则里的权限 ∈ 接口鉴权条件 ∈ 测试用例的权限断言；
- 前端每个状态（空/错/加载）在测试里都有对应用例。
